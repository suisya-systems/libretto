# 会議メモの取り込みを本物の Gemini のメモで確かめる

GitHub #47 の確認手順（[`implementation.md` 6.7](../implementation.md)）。#12 で取り込んだ会議メモの読み取りは、偽の Google でしか確かめていない。行動項目の節の見出しの語・節の終わり・担当の書き方は、日本語と英語のメモで見た形から推して書いてある（`host/src/intake/meet.ts` の `START` / `END` / `FOOTER` / `BULLET` / `CHECK` / `NOTHING` / `assigneeOf`）。テスト（`npm run verify`）は偽の Google で回り、ここは確かめない。

## オーナーが用意するもの

Gemini の「メモを取る」をオンにした会議を、次のどれかが揃うように開く（揃えられたものだけでよい。揃わなかったものは記録に書く）。

| # | 会議 | 確かめること |
|---|---|---|
| M1 | 自分が主催し、行動項目に**自分の名前**が担当で入る会議 | 見出しの語・節の終わり・担当の書き方・本人の当たり方 |
| M2 | M1 と同じで、行動項目に**ほかの人だけ**が担当の項目もある会議（M1 と同じ会議でよい） | ほかの人の項目が候補に出ないこと |
| M3 | **ほかの人が主催**し、自分が招待された会議 | 共有された会議のメモが `drive.meet.readonly` で見えるか |
| M4 | 行動項目が出ない短い会議 | 「行動項目なし」と「見つけられません」の分かれ方 |
| M5 | 英語のメモ（Meet の言語が英語）。あれば | 英語の見出しと注意書き |

メモは会議の後に Gemini が書き足す。会議が終わってから 10 分より後に確かめる（ホストも 10 分以内のメモは読まない）。

## 手順 1: 書き出しで切り出しを確かめる（ホストを起こさない）

1. メモの Google ドキュメントを開き、「ファイル」→「ダウンロード」→「書式なしテキスト（.txt）」で保存する。置き場は**リポジトリの外**（例: `~/libretto-meet-check/M1.txt`）。中身は会議の内容なので、リポジトリに入れない・Issue や記録に貼らない。ホストは Drive の API で同じ `text/plain` の書き出しを読む（同じ形であることは手順 2 で確かめる）
2. 次を流す。網に出ず、モデルを呼ばず、何も書かない

   ```
   npm run verify:meet -- ~/libretto-meet-check/M1.txt --title '<ドキュメントの題名>' --name '<Google のアカウントの表示名>' --email '<連携するアドレス>'
   ```

3. 見ること

   | 出力 | 合っているとき | 合わないときの直し先 |
   |---|---|---|
   | `title:` | `ok`、会議名と日時が題名どおり | `NOT MATCHED` → `TITLE` |
   | `result:` | ドキュメントの行動項目の節（「推奨される次のステップ」など）の項目の数と同じ。M4 は `none` | `unreadable` → 見出しの語（`START`）。数が多い → 節の終わり（`END` / `FOOTER`）。「ありません」の類の行が項目になる → `NOTHING` |
   | 項目の文 | 頭の点・番号・チェックの印（`☐` や `[ ]`）が外れ、項目の文だけ | `BULLET` / `CHECK` |
   | `assignee=` | 項目の担当の名前（M2 のほかの人の名前も） | `(none)` なのに担当が書いてある → `assigneeOf` |
   | `if-mine=` | 自分が担当の項目が `高` | `中` → 表示名とメモの名前の書き方の違い（姓名の順・ローマ字など。下の「既知の制限」） |

4. 合わないときは、見出しの行・節の終わりの行・項目の頭の文字（担当の名前は伏せる）を窓口に渡す。直すのは `meet.ts` のその定数と、`host/test/meet.test.ts` の「書き出しの崩れ」のテスト、`implementation.md` 6.7 (3)。

## 手順 2: 本物のホストで取り込む

1. ふだんの家でホストを起こし（`npm start`）、設定の Google の行で「連携する」。同意画面で**全部の許可を付けたまま**進める
2. 設定の Google の行に「会議メモは、直近 14 日の「Gemini によるメモ」を見ます。…」が出て、連携し直しの文が出ないこと
3. 次の取り込みの回（15 分ごと）を待つ。ホームを見る
   - M1 の自分の項目が「依頼の候補」に**会議・高**で出る。カードの「担当」が名前、「メモを開く」がそのメモ
   - M2 のほかの人だけの項目は出ない。担当の書かれていない項目は**推測・低**（「ほかに N 件…」の中）
   - M4 は候補の欄の下の「読んだ会議メモ」に「行動項目はありませんでした」。「見つけられませんでした」になったら、手順 1 の `result:` と比べる（手順 1 が `none` でここが「見つけられません」なら、API の書き出しが .txt と違う）
4. M1 の候補で「進める」→ 入口の依頼書の下書きに、行動項目の内容が入っていること

## 手順 3: 共有された会議（M3）

手順 2 のあと、M3 のメモが次のどれかで見えれば見えている: 候補に出る・「読んだ会議メモ」に 1 行出る。どちらにも出ないときは、M3 のメモを自分が Drive で開けるか（主催者が共有しているか）を先に確かめる。開けるのに出ないなら、`drive.meet.readonly` では共有された会議のメモが見えないので、記録に書いて窓口に渡す（権限の選び直しは 6.7 (1) の設計の判断になる）。

## 手順 4: 同意画面で Meet の権限だけ外す

1. Google のアカウントの「サードパーティ製のアプリとサービス」で libretto のアクセスを外し、設定の Google の行で「連携する」をもう一度押す。先に外すのは、連携の URL が前に許した権限を引き継ぐ（`include_granted_scopes`）ので、外さずに連携し直すとチェックを外しても Meet の権限が残るため
2. 同意画面で Google Meet のファイルの許可のチェックだけを外して進める
3. 設定の Google の行に「会議メモの行動項目を取り込むには、もう一度「連携する」を押して、Google Meet のファイルの許可を足してください。」と「連携する」が出ること。Gmail の取り込みと Google ドキュメントへの保存は動くこと
4. もう一度「連携する」で全部の許可を付けて戻す

## 記録に書いてよいもの

このリポジトリは公開されている。記録には**会議名・項目の文・担当の名前・メモのリンクを書かない**。書くのは、見出しの語・節の終わりの行の語（Gemini が付ける決まった文だけ）・項目の頭の印・合った / 合わなかったと件数。記録は `docs/verification/<YYYY-MM-DD>-meet.md` に置く。

| 項目 | 値 |
|---|---|
| 確かめた日 | |
| 揃った会議（M1〜M5） | |
| 行動項目の節の見出しの語（日本語 / 英語） | |
| 節の終わりの行（次の見出し・注意書きの書き出し） | |
| 項目の頭の印（点・番号・チェック） | |
| 担当の書き方（`[名前]` か、ほかの形か） | |
| 本人の項目の確信度（高 / 中） | |
| 手順 1 と手順 2 の `result` が同じか | |
| 共有された会議のメモが見えたか | |
| Meet の権限だけ外したときの設定の表示 | |
| 直したこと | |

## 既知の制限

- 本人の当たり方は、Google のアカウントの表示名かアドレス全体が項目の文にあるかで決める。メモの名前が表示名と違う書き方（姓名の順が逆・ローマ字・名だけ）だと、本人の項目でも**会議・中**になる（候補には出る）。手順 1 で `中` が続くなら、記録に書き方の違いだけを書いて窓口に渡す。
