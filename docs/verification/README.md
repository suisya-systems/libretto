# 実モデル検証

本物のモデルで libretto を 1 本流し、記録を `docs/verification/<YYYY-MM-DD>.md` に残す（同じ日に 2 回以上流したら `<YYYY-MM-DD>-1.md`・`-2.md`）（[`implementation.md` 11.1・11.3](../implementation.md)）。テスト（`npm run verify`）は全部偽のモデルで回り、ここだけが本物のモデルを呼ぶ。CI では回さない。

## 流し方

前提: Claude Code にログイン済み（`claude --version` が通る）。Linux / WSL2 は `bubblewrap` と `socat`。

```
npm run verify:live                              # 新しい家で起こす（上限 3,000 円）
npm run verify:live -- --cap 2000                # 上限を変えて新しく起こす
npm run verify:live -- --home <家>               # 同じ家で起こし直す（再開の確かめ）
npm run verify:live -- --home <家> --report      # 起こさずに記録の下書きだけ作り直す
```

1. `npm run verify:live` を流す。画面を作り直してから、新しい家（`~/libretto-verify/<日時>-XXXXXX`）でホストが起きる。普段の `~/libretto` は使わない
2. ターミナルに出たペアリングの URL をブラウザで開く
3. 画面だけで 1 本流す: 会話で頼む → 入口で承認 → （渡してほしいものがあれば貼る）→ 検品を待つ → 承認 → 送付 → 完了
4. 終わったら（途中で止まっても）ターミナルで Ctrl-C。`<家>/verification.md` に記録の下書きができる
5. 下書きの人が書く欄を埋め、`docs/verification/<YYYY-MM-DD>.md`（同じ日の 2 回目からは `-N`）として取り込む

費用: この家の中の全部（会話・入口・案件）で上限まで。上限に達すると案件は「費用の上限」で止まる。案件 1 件の上限（1,500 円）も効く。全体上限は月（JST）で区切るので、別の月に同じ家を起こし直すことはできず、月末の残り 2 時間を切っていると新しく始められない。

生の出力: 呼び出しごとに `<家>/debug/` に残る（受け入れ規則に落ちた理由も）。崩れた出力を調べるのに使い、リポジトリには入れない。

## 記録に書いてよいもの

このリポジトリは公開されている。記録には**本文・会話・依頼の題・確認項目の文を書かない**。自動で埋める欄は、状態・出来事の種類・費用・件数だけになるように作ってある（本人が「止める」に付けた文も写さない）。題材は公開してよい言い方で 1 行にする。`debug/` の中身は写さない。
